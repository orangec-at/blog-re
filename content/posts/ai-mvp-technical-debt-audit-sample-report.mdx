You don't need a vague review that says "the code is messy." You need something you can use to decide.

- What could break first
- Why it's a business risk
- What to fix first
- Whether you can launch publicly now, or need a private pilot / stabilization first

  title="System map: does it map the product flow and trust boundaries?"
  body="The goal isn't a perfect diagram of the whole codebase. What matters is finding where trust can break — between the browser, app routes, auth/session, the database, and third-party providers."
  checks={[

```text
Browser UI
  → App routes / server actions
  → Auth & session boundary
  → Database / ownership queries
  → Calendar provider / email provider
  → Runtime logs / error monitoring
```
