Founder에게 필요한 것은 “코드가 지저분합니다”라는 막연한 리뷰가 아닙니다. 필요한 것은 의사결정 산출물입니다.

- 무엇이 먼저 깨질 수 있는가
- 왜 비즈니스 리스크인가
- 무엇을 먼저 고쳐야 하는가
- 지금 공개 출시해도 되는가, 아니면 private pilot / stabilization이 먼저인가

</ExpertInsight>

```text
Browser UI
  → App routes / server actions
  → Auth & session boundary
  → Database / ownership queries
  → Calendar provider / email provider
  → Runtime logs / error monitoring
```

<ExpertInsight source="Founder-facing translation">
  “보안 문제 가능성 있음”보다 “User A가 User B의 예약 정보를 볼 수 있는 경로가 아직 증명되지 않음”이 founder에게 훨씬 유용합니다.
</ExpertInsight>
